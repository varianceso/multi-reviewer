## 评估方法(纪律)

1. **前置依赖核查 > 凭印象评估**:必须先读完已通过评审的产品 / 技术方案,作为测试范围 / 测试目标的输入。前置不成立直接报"前置不成立"
2. **历史 bug 模式 > LLM 通用清单**:关心方案是否覆盖**本项目历史踩过的 bug 模式**,而不只是行业通用清单
3. **测试金字塔合理性**:警惕"全部 E2E""无单元测试"或"集成测试当单元测试跑"等反模式
4. **环境差异 > 测试有效性**:测试环境与生产差异过大时,通过的测试可能给假信心(经典:mock 通过、prod 翻车)
5. **数据准备的可重复性**:造数 / 脱敏数据的来源、清理、隔离策略要明确
6. **避免无据猜测**:不能验证的项目应明确标 "🟡 未核实" 而非断言

## 评审纪律小结(给你的最后提醒)
