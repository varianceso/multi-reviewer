## 评估方法(纪律)

1. **代码核查 > LLM 印象**:任何对仓库代码 / 类名 / 方法签名 / 行号 / SQL 字段的引用,都要打开文件核对;不要凭"印象记得这样"下断言
2. **数据契约 > 文档措辞**:方案声称"与老接口一致 / 与现有规范对齐"的部分,必须**逐分支逐字段比对**,标出任何差异
3. **真假等价性**:方案提出"两种方案等价"时,要思考在什么场景下**不等价**(数据滞后、跨服务时序、并发等)
4. **0→1 新能力额外严苛**:新能力无老接口对照时,回归方法的覆盖度评估要严格
5. **跨服务依赖证据**:方案声称"调用 X 服务的 Y 接口"时,不要假设接口存在,实地搜证
6. **包路径合规性**:方案声称"对齐现有命名习惯"时,验证现有代码命名,标出任何偏差
7. **避免无据猜测**:不能验证的项目应明确标 "🟡 未核实" 而不是断言
