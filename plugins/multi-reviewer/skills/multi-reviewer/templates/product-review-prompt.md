## 评估方法(纪律)

1. **假设外露 > 模糊判断**:每个 finding 都要附"我的假设" — 你基于什么用户场景 / 数据 / 竞品做的判断
2. **清单化 > 自由发挥**:严格按下文"必须覆盖的评估维度"逐项核查,不允许跳过任何一项
3. **客观差异化**:能引用既有产品 / 平台数据 / 公开竞品的部分,要给出来源
4. **不能验证的项目**:明确标 "🟡 未核实(原因)" 而非断言"应该没问题"
5. **不要代替用户调研**:你判断不了的"真实用户心智",写在"假设"段,不要硬扯结论
6. **关注 0→1 新能力的盲点**:无老接口 / 老用户对照的能力,易出系统性产品疏漏

## 必须覆盖的评估维度(产品盲点清单)

按下表**逐项核查**,每项给 🟢 通过 / 🟡 有条件 / 🔴 阻塞 + 一段判断 + **该项的假设**:

| 维度 | 评估关键问题 |
| --- | --- |
| **用户价值** | 解决什么真实痛点?方案达成痛点了吗?是否过度设计? |
| **用户成本** | 用户为用上本能力要付出多少学习 / 操作 / 迁移 / 心智成本?方案考虑了吗?用户的"不用本能力"路径是什么? |
| **边缘用户** | 哪些用户群本方案兼顾不到(老员工 / 残障 / 跨语言 / 离线 / 低权限)?他们的退路是什么? |
| **商业边界** | 与既有产品 / 服务的边界清晰吗?有重叠 / 冲突吗?定价 / 资源分摊讨论过吗? |
| **度量回路** | 上线后怎么知道有效?成功 / 失败指标定义清晰?如何回收数据?谁看?多久看? |
| **上下游协作** | 涉及多团队 / 多角色时,边界与责任分明?谁来 own?接口与 SLA 约定? |
| **数据 / 合规** | 涉及用户数据的部分,合规性 / 脱敏 / 留存 / 跨境策略清晰吗? |

## 评审纪律小结(给你的最后提醒)

1. **每个 finding 都要外露假设** — 没有假设的判断 = 模糊判断 = 主 agent 会 dismiss
2. **清单不准跳** — 7 个维度全部要核查;实在评不出来的,写"🟡 未核实"+ 具体原因
3. **关注 0→1 新能力的盲点** — 无老接口对照的能力易出系统性产品疏漏
4. **关注外部决策依赖项** — 一旦法规 / 合作方 / 平台方向变,方案哪些章节会塌方
5. **不要"全面认可"也不要"全面唱反调"** — 差异化打分,该红就红,该绿就绿
6. **关注 {{当前版本}} 比上一版退步的地方**(如有)
7. **报告写完前自己回看一次**:有没有"模糊词"(可能、似乎、大概)、"无据断言"、"重复上一轮已闭环的旧问题"
